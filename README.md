# CraftApps for Android 📱

Unofficial Android ports of the [storytold](https://github.com/storytold) "craft" creative app suite — real desktop-class tools, running natively on your tablet or phone. Plus a launcher app that keeps them all up to date.

> **Disclaimer:** This project is vibe-coded in my free time. It's unofficial, experimental, and provided as-is — I'm not responsible for anything that may or could happen from using it.

## The lineup

| App | What it does |
|---|---|
| **PhotoCraft** | Layer-based image editor (think Photoshop-style painting, filters, adjustments) |
| **DesignCraft** | UI/graphic design tool for layouts, mockups, and interface work |
| **VectorCraft** | Vector graphics editor — logos, illustrations, bezier everything |
| **LightCraft** | Photo development and RAW processing (think Lightroom-style) |
| **PdfCraft** | PDF viewer and annotator — read, mark up, sign |
| **EffectCraft** | Motion graphics and visual effects |
| **FilmCraft** | Video editor — timeline, cuts, transitions, export |
| **CraftApps Launcher** | Home base: install, update, and open all of the above |

All seven apps share one codebase pattern: a thin Android shell (Kotlin/Java + Gradle) over a Rust core built with [egui](https://github.com/emilk/egui). They look and feel like the desktop originals, with touch, pen, and tablet UI.

## Install

Grab the APKs from the [releases page](https://github.com/areilly111/CraftApps-Android/releases). Each app has its own release series (see below).

1. **Allow installs:** Android will ask you to enable *"Install unknown apps"* for your browser or file manager the first time. That's normal — these aren't on the Play Store.
2. **Install the APKs** you want (or just the Launcher — it can install the rest).
3. **Grant All-files access:** on first launch, each app asks for *"All files access"* (`MANAGE_EXTERNAL_STORAGE`). This is how they read/write your documents in `/sdcard/CraftApps/`. Without it they can't open or save anything outside their sandbox.

**Easiest path:** install just the **CraftApps Launcher** APK, grant it the permissions above, and use it to install/update the other apps. It checks GitHub releases, downloads new versions, and verifies them before installing.

> **Heads up:** the repo is currently **private**, so the in-app updaters can't see releases yet — they'll just say no updates are available. Install from the APKs directly for now. Once the repo goes public, updates light up automatically.

## Build it yourself

Want to build from source? Here's the full recipe. Tested on Ubuntu; should work on any Linux with enough RAM (these are big builds).

### Prerequisites

- **Rust** with Android targets:
  ```bash
  rustup target add aarch64-linux-android x86_64-linux-android
  ```
- **JDK 17** (Gradle needs it)
- **Android SDK + NDK** (NDK r27 tested) — set `ANDROID_HOME` / `ANDROID_SDK_ROOT`
- **Gradle** (the wrapper in each app dir handles the version)

Each app lives in its own folder (`photocraft/`, `designcraft/`, …) with an `android/` Gradle project and an `upstream/` checkout of the original source plus the port crate.

### Build one app

```bash
cd ~/workspace/craftapps-android
./scripts/build-apk.sh photocraft
```

That builds the Rust `.so` for arm64 + x86_64, drops them into the Gradle project's `jniLibs`, assembles a signed release APK, and copies it to `~/workspace/your_files/PhotoCraft-<version>-universal.apk`.

Swap `photocraft` for `designcraft`, `vectorcraft`, `lightcraft`, `pdfcraft`, `effectcraft`, `filmcraft`, or `launcher`.

**Fair warning:** clean builds take 30–60 minutes per app the first time (Rust compiling egui/wgpu for two architectures). Incremental rebuilds are much faster. Go make coffee.

> Signing: release APKs are signed with persistent keystores (git-ignored, never committed). **Don't lose them** — Android refuses to update an app if the signing key changes. PhotoCraft has its own keystore; the other six apps + launcher share a suite keystore.

## Updating from upstream

When storytold ships a new version of an app, the port needs re-pinning. Each app has a script for this:

```bash
./scripts/pin-upstream-photocraft.sh v0.7.0
```

What it does:
1. Clones the upstream repo at the new tag into a scratch dir
2. Copies the Android port crate over
3. Re-applies the port's small patch set (documented at the top of each script — usually an eframe feature gate, a workspace dep tweak, and the port registration)
4. Bumps the port version (`0.6.0-port5` → `0.7.0-port1`)
5. Swaps the result into the app's `upstream/` dir

Then rebuild and release:

```bash
./scripts/build-apk.sh photocraft
# ... test it ...
# tag + GitHub release (see below)
```

The patch lists were generated by diffing each port against pristine upstream, so if upstream restructures something the script fails loudly instead of silently producing a broken build. Check the script header for the exact patch list per app.

## Releasing

Releases are **per-app**, tagged like `photocraft-v0.6.0-port5`. The flow:

1. Build the APK (`build-apk.sh`)
2. Generate checksums: `sha256sum *.apk > SHA256SUMS.txt`
3. Create a GitHub release on the tag, attaching the APK + `SHA256SUMS.txt`
4. Paste the upstream release notes into the body

The in-app updater polls this repo's releases, filters tags by prefix (`photocraft-`, `designcraft-`, …), and offers the `*-universal.apk` asset after verifying its SHA-256. One tag series per app means each app updates independently — a FilmCraft fix doesn't force a 780 MB re-download of everything.

## Contributing

This is a free-time project, so: PRs welcome, but no promises on review speed. If something's broken, an issue with a logcat (`adb logcat`) goes a long way. If you fix it yourself, even better.

A few ground rules from experience:
- **Bump `versionCode`** on every shipped build (Android treats a non-increasing versionCode as a downgrade and refuses to install it).
- **Don't commit keystores.** Ever.
- **Only push working code.** If the build's red, it stays local.
- Newest builds only — don't ship old versions alongside new ones.
